# 增强前后对比示例（Before / After）

以下均为插件开启 `mode: auto` 后的真实链路效果示意：左列是对话框里的原始输入，右列是 Agent 实际收到的提示词。

## 示例 1：模糊的开发需求

**Before**

> 帮我写个爬虫

**After**

> 编写一个 Python 爬虫脚本：抓取给定网址列表中每个页面的标题和正文，按天保存为 CSV 文件（列：url、title、content、date）。要求：请求间隔不少于 1 秒；单页失败自动重试 3 次；请求超时 10 秒；使用 requests + BeautifulSoup；代码附中文注释和使用说明；不涉及任何需要登录或付费的站点。

## 示例 2：一句话修 Bug

**Before**

> 这个 bug 修一下

**After**

> 定位并修复当前仓库中的构建失败。步骤：先运行 `pnpm run build` 复现并记录报错；给出根因分析（引用具体文件路径与行号）；实施最小修复；重新运行构建确认通过；最后用不超过 10 行总结改动内容。

## 示例 3：日常口语化请求

**Before**

> 把我桌面那个报告整理得好看点

**After**

> 优化桌面上指定报告文档的排版：统一标题层级与字号（一级 16pt、二级 14pt、正文 11pt），表格套用统一表头底色，图片居中并补图注编号，页脚添加页码。仅调整格式，不得改动任何文字内容。完成后列出所有修改项。

## 不触发增强的情况

| 输入 | 原因 |
|---|---|
| `/plan 重构登录模块` | 斜杠命令，永不改写 |
| `继续` | 长度低于 `minPromptLength`（默认 4） |
| （粘贴 8000 字需求文档） | 超过 `maxInputChars`（默认 4000），视为已是完整提示词 |
| （带图片/文件附件的消息） | 含非文本块，保守跳过 |

## 增强调用的回退行为

增强调用失败（网络错误、超时 20s、模型路由不可用）时，插件**原样放行原始输入**并在控制台记录：

```
[dsh-prompt-enhancer] enhance failed, pass through original: prompt-enhancer timeout
```
