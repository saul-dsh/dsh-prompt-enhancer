# 增强前后对比

以下为三档强度的改写效果示意，实际输出取决于所用的模型。规律是一致的：档位越高，补全的信息越多，结构越完整。

## 同一句话，三档差异

**原始输入**

> 帮我写个爬虫

**Low**（只修歧义，不动结构）

> 帮我写一个爬虫脚本，抓取指定网页里的标题和正文。

**High**（补全约束和输出形式，默认档）

> 编写一个 Python 爬虫脚本：抓取给定网址列表中每个页面的标题和正文，按天保存为 CSV（列：url、title、content、date）。要求请求间隔不少于 1 秒，单页失败自动重试 3 次，请求超时 10 秒，代码附中文注释和使用说明。

**Max**（第一性原理重构，假设逐条标注）

> 编写一个可重复运行的网页内容采集脚本，把指定站点的文章结构化保存下来。
>
> **目标**：给定一批入口 URL，产出按天分文件的 CSV，字段为 url、title、content、date。
> **约束**：请求间隔不少于 1 秒；单页失败重试 3 次；超时 10 秒；遵守 robots.txt；不抓取需要登录的页面。
> **假设**：(assumption: 目标站点是静态 HTML，无需浏览器渲染)；(assumption: 单机运行，不需要分布式调度)；(assumption: 数据量在万级以内，CSV 足够)。
> **产出**：脚本文件 + 依赖说明 + 运行示例。
> **验收**：连续跑两次，第二次不产生重复行；中断后重跑能跳过已完成 URL。

## 更多示例（High 档）

| 原始输入 | 增强后 |
|---|---|
| 这个 bug 修一下 | 定位并修复当前仓库中的构建失败：先运行 `pnpm run build` 复现报错，给出根因分析（引用具体文件与行号），完成最小修复后重新运行构建验证通过，并总结改动点。 |
| 把我桌面那个报告整理得好看点 | 优化指定报告文档的排版：统一标题层级与字号，表格套用统一表头底色，图片居中并补图注编号，页脚添加页码。仅调整格式，不改动任何文字内容，完成后列出所有修改项。 |
| 做个网站 | 用单个 HTML 文件制作一个「个人书签导航页」：顶部搜索过滤，卡片式分组展示书签（名称、URL、备注），支持增删改（localStorage 持久化），浅色主题、移动端适配，无外部依赖。 |

## 不触发增强的情况

| 输入 | 原因 |
|---|---|
| `/plan 重构登录模块` | 斜杠命令，永不改写 |
| `继续` | 长度低于 `minPromptLength`（默认 4） |
| 只发了图片或文件 | 非纯文本消息，不改写 |
| 超过 `maxInputChars`（默认 4000 字符） | 视为已经是完整提示词 |

## 增强失败时

增强调用失败（网络错误、超时、模型路由不可用、输出失控）时，插件**原样放行原始输入**并在控制台记录：

```
[dsh-prompt-enhancer] enhance failed, sending original: prompt-enhancer timeout
```

发送拦截路径不会因此卡住，用户的消息照常发出。

## 关于「自动增强」开关

关闭时点发送不拦截，输入什么就发什么，只有主动点 ✨ 才会增强。默认是关闭的。
